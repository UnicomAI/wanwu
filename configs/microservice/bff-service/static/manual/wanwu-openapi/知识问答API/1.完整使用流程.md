# 完整使用流程

> **典型流程**：新建知识问答 → 更新配置（挂知识库/问答库、选模型）→ 草稿态调试问答 → 发布 → 发布后正式问答。
> 需要多轮上下文与历史记录时加「创建会话」。

## 知识问答查询

| 用途 | 接口 | 说明 |
| --- | --- | --- |
| 查询列表 | `GET /v1/rag/list` | 全部知识问答（含草稿态与已发布态） |
| 按名称筛选 | `GET /v1/rag/list?name=关键字` | 名称模糊匹配 |
| 查询详情（草稿态） | `GET /v1/rag/info?uuid={uuid}` | 默认返回草稿态 |
| 查询详情（已发布态） | `GET /v1/rag/info?uuid={uuid}&published=true` | 返回已发布版本 |

> 返回的 `uuid` 是后续所有知识问答接口的入参主键。

## 会话与历史管理

### 已发布会话

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 会话列表 | `GET /v1/rag/conversation/list` | 按 uuid 分页 |
| 历史消息 | `GET /v1/rag/conversation/detail` | 按 conversation_id 分页，含检索命中与耗时 |
| 清空历史 | `DELETE /v1/rag/conversation/clear` | 保留 conversation_id，可继续问答；传 detail_id 则只删该条 |
| 删除会话 | `DELETE /v1/rag/conversation` | 移除 conversation_id，下次问答需重新创建 |

> **`clear` 还是 `delete`**：想保留同一会话继续问答用 `clear`；不再使用用 `delete`。

### 草稿态会话

> 草稿态每个知识问答只有一条会话，全部接口通过 `uuid` 定位，无需 `conversation_id`。

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 草稿历史消息 | `GET /v1/rag/conversation/draft/detail` | 按 uuid 分页 |
| 删除草稿历史 | `DELETE /v1/rag/conversation/draft` | 传 detail_id 则只删该条消息 |

## 生命周期管理

| 操作 | 接口 | 说明 |
| --- | --- | --- |
| 列出全部 | `GET /v1/rag/list` | 含草稿态与已发布态 |
| 编辑基本信息 | `PUT /v1/rag` | 名称、描述、图标 |
| 删除知识问答 | `DELETE /v1/rag` | 同时删除其已发布版本，**不可恢复** |
