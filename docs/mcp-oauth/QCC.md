# 企查查 MCP：统一入口与按需工具发现

依赖通用 MCP OAuth 功能。广场卡片只建立 **一条**企查查连接，不再把旧的五服务
清单当作完整能力。用户通过系统浏览器授权，无需粘贴 API Key。

## 配置与准入

按 [通用部署说明](README.md) 配置 `qcc.example.json`，替换本部署 HTTPS relay
与 Web 回调地址，使用独立加密密钥及持久卷。Client Name 为 **Wanwu**，scope 为
`mcp:tools`，授权与调用使用 `https://agent.qcc.com/mcp/company/stream`。
`clientId` 留空时动态注册公开客户端，使用 PKCE S256。

此 URL 可由企查查侧按客户端/账号授权绑定提供统一目录；须由服务提供方确认
Wanwu 已获统一入口准入。旧授权若仍返回 company 子集，应重新授权并核查准入，
不能把子集当作统一入口成功，也不能靠添加五个旧连接补齐历史能力。

## 按需发现、定义读取、调用

示例启用 `onDemand: true`。所有调用链经同一托管入口，模型只接收三个工具定义：

1. `mcp_search_tools`：检索远端完整目录，仅返回匹配名称及摘要；支持空查询浏览和 offset 分页。
2. `mcp_tool_detail`：按名称读取一个工具的完整定义及参数 schema。
3. `mcp_call_tool`：按发现的名称和参数执行，保留提供方结果及业务错误。

服务端遍历 `tools/list` 的 cursor 分页；当前业务目标是 186 项跨模块工具，
包含历史数据。**186 不是固定上限或硬编码名单**，工具可用性以当前授权目录为准。
每次操作建立独立上游 MCP 会话、重新读取目录，避免跨用户缓存、过期权限和重启后的
陈旧工具列表。模型不会在连接时收到全部业务 schema；仅明确读取的定义进入工具结果。
搜索为名称/描述关键词匹配（多个词取交集），并非语义检索；可用短关键词或空查询分页。
每页最多 10 条摘要；安全边界为 100 个目录分页、5000 项工具、每操作 60 秒，
超过边界明确报错，不静默截断目录。当前适用于无跨调用会话依赖的查询工具。

授权刷新、epoch 校验在每次上游 HTTP 请求前执行。401 不自动重放工具调用。
解绑使整个统一连接失效；重启从加密存储恢复授权，无需逐模块配置。
重新授权后保存连接以更新内部引用。若曾部署五连接示例，先解绑并删除旧连接，
替换配置、重启 BFF，再新建统一连接；不要保留旧卡片造成混淆。

## 验证与上线边界

自动化模拟 186 项目录分为两页，验证历史专利在第二页可发现、schema 只按单项返回、
发现操作不执行业务调用、未知工具被拒绝、扩展为 187 项后自动可见、重启恢复及解绑。
通用授权测试覆盖并发刷新和跨进程持久化，旧多目标测试仅作为通用兼容回归保留。

以上是模拟协议证据，尚未用真实 Wanwu 客户端完成企查查准入、短信登录、全目录快照、
真实历史查询与模型逐轮输入验收；不宣称全部 186 项均已执行或已上线。
